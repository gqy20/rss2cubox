# 阅读工作台

前端沿用 Next.js App Router，采用已确认的 B 风格：象牙白、陶土色与橄榄色，宋体编辑标题、无衬线阅读列表。全站使用 `app/journal/Shell.tsx` 和 `app/styles/journal.css`。

## 页面

| 路径 | 内容 |
| --- | --- |
| `/` | 刊物式首页、跨来源重点文章、最新洞察、政策阅读入口 |
| `/briefing` | 完整趋势、弱信号与建议，以及最近30期历史简报 |
| `/signals` | 搜索、来源/日期/标签/重要性筛选、滚动续载和点击阅读 |
| `/policies` | 政策全文库，按地区、阶段、文件类型和分析状态筛选 |
| `/policies/[id]` | 关键条款、原文引句、适用主体、日期与已抓取全文 |
| `/topics?id=...` | 信号簇文章与关键词匹配的候选政策对读 |
| `/predictions?id=...` | 验证窗口、支持条件、反证条件和实际复盘 |
| `/monitor` | 异常优先的信源目录、最近12轮、内容产出与统计 |
| `/saved` | 当前浏览器收藏，使用 localStorage，不跨设备同步 |

首页与政策、专题、预测、监控在服务端读取 `DATABASE_URL`。`lib/journal-store.ts` 使用共享连接池、连接/语句超时及参数化查询，按模块降级显示不可用状态，不用示例数据补齐。技术信号继续支持 `API_SOURCE` 非 local 时的 IC 读取；政策与监控仍需要本地 PostgreSQL。

列表和详情通过 `/api/reader/[kind]`（signals / article / policies / policy）读取。列表每批30条，通过游标续载；全文只在详情中读取（搜索列表只返回命中片段）。搜索和筛选在数据库截取批次前执行。客户端取消过时请求，避免快速切换时错配文章与标题。旧 `/api/signals` 与 `/api/predictions` 接口保持兼容。

## 数据口径

- 文章总量是已收录总数，不是今日新增；重点文章是 `importance_score >= 4`。
- 文章已有分析：`hidden_signal`、`reason`、`actionable` 至少一个非空，不把 RSS 描述直接视为 AI 分析。
- 政策已分析：`enriched_at IS NOT NULL`。预筛会跳过低相关文件，因此未分析数量不是待处理任务数。
- 专题政策来自实体/关键词检索，明确标记为候选关联，不推断政策适用性。
- 监控图表按北京时间的首次入库日期统计。科技来源按同一信源、同一运行编号合并请求后展示最近12轮；未采集阈值可选24h/48h/7天，不能据此断言在线状态。
- 预测没有复盘时不显示命中率。日期缺失时显示未明确；不生成虚构的征集截止提醒。
- 刷新只读取数据库，不调用模型或触发采集。

## 本地验证

```sh
cd web
npm run dev
npm run test:run
npm run build
```

主要组件为 `Reader`（技术/政策列表与阅读）、`Predictions`、`TrendChart`、`Shared` 和 `Actions`。`journal-utils.ts` 中的来源多样性、来源 URL 校验与洞察归一化有单元测试；查询测试覆盖筛选参数化、分页、日期与关键词转义。

## 搜索交互

顶部是唯一的文章/政策搜索入口，范围可显式切换。首页等非列表页面按 Enter 或箭头提交；列表页输入停顿350ms后自动提交，Enter立即提交，中文组词期间不搜索。清空关键词保留筛选，重置筛选保留关键词。关键词、筛选和手动选择的记录使用URL保存，支持刷新与浏览器返回。

查询仅匹配标题、来源、摘要、分析、标签/实体与正文；政策同时匹配机构、适用主体和关键条款。内部ID、链接和评分字段不参与文本匹配。标题命中优先，其余命中展示截取片段与字段名称，关键词用原生mark高亮。`%`与`_`按普通字符处理。客户端取消旧请求并验证查询归属，避免过时结果覆盖当前查询。

## 连续阅读面板

`/signals` 与 `/policies` 占据完整视口，顶部搜索、精简页面标题和筛选固定；桌面端列表与详情正文分别滚动，详情标题及操作保持可见。手机一次显示列表或正文，进入正文后收起页面标题和筛选，保留搜索与返回入口。首页和独立政策详情仍使用普通页面滚动。

列表接近底部时自动请求下一批，另保留可键盘操作的“继续加载”作为辅助入口。追加不改变选中文章，失败后保留已有数据并原位重试，到底时展示结束状态。客户端按ID去重，切换查询时取消旧请求。

游标包含查询指纹、首次加载时间、标题匹配优先级、微秒时间戳和ID。PostgreSQL查询使用键集边界，限定首次入库时间不晚于本次浏览快照，避免新增入库记录打乱续载；既有记录的编辑仍可能影响排序，客户端另行去重。旧page参数保留兼容，新界面不显示页码。IC模式按规范化后的时间与ID续载，其入库快照能力取决于上游数据。

同一标签页内缓存最近6个查询的已加载列表与滚动位置，切换详情或路由后返回时恢复。硬刷新会开始新的阅读会话。页面可见时每60秒检查新内容，只显示更新提示，不自动插入列表；用户点击提示或刷新按钮后才更新浏览快照。

验证覆盖游标精度与查询绑定、续载去重/互斥、失败重试、过时请求、缓存恢复及新内容提示；浏览器实测桌面独立滚动、自动续载、政策详情返回和移动端返回位置。

## 信源监控目录

`monitor-store.ts` 合并 `feeds.txt` / `policy_sources.toml` 配置、运行记录与内容统计。优先展示配置别名，再用已入库来源名或域名。科技停用桶按后端 `FEED_SECTIONS_DISABLE` 读取（根目录 `.env` 优先），政策按 `enabled` 识别；不在当前配置中的旧记录标为历史。配置无法读取时降级为数据库记录，不把未知配置误当成停用。

科技运行以 `(feed_url, run_id)` 归并，缺少运行编号的旧记录独立处理：任何备用请求成功，整轮成功；无成功但有可解析空结果则为空；再判断失败和跳过。条数取成功请求最大值，避免重复累加；耗时为该轮各请求累计值。状态历史保留最近12轮，最近成功时间从全部历史中计算。政策表只有最新一次运行，其余历史格留空，不伪造时间序列。

默认“需要关注”展示失败、超过阈值未采集、连续至少3轮空结果和未运行的启用来源，停用及历史源不计入异常。状态分布可点击筛选，404等错误类别进一步定位原因；HTTP分类不把443端口当作响应码。

“内容产出”按信源展示累计收录/已分析/重点数。重点占比以有效评分样本为分母，至少20条才展示；科技重点为重要性4–5，政策重点为已分析且相关度4–5，不合并为跨类型的质量总分。

点击信源可查看运行明细、最新12条/重点12条内容，以及真实参与的技术专题。详情接口 `/api/monitor/source?id=...` 使用信源类型与键的MD5作稳定标识（不是授权凭证），实际键在服务端映射并用于参数化查询；显示的订阅地址和错误信息去除嵌入凭据及敏感查询参数。请求明细最多100条。

目录和详情分别滚动，手机显示单一面板；筛选与选中来源写入URL，保留当前标签页中的目录滚动位置。入库趋势和统计口径移到“统计”视图。页面显示数据快照，刷新只读数据库，不触发采集或模型调用。

## 专题选择与对读

专题选择改为标题旁的可搜索纵向面板，支持名称/实体/关键词匹配、方向键/Enter选择及Escape关闭。默认排除 `invalid`、`archived` 和无关联文章的专题；可主动勾选查看被排除的记录。专题状态使用中文标签，计数从实际文章关联表计算，避免与缓存计数不一致。

摘要默认收起长文本；无候选政策时使用全宽文章列表和简短提示，不保留空的半屏。专题首页按与阅读列表相同的发布时间顺序展示前8篇，通过 `/signals?topic=<id>` 阅读全部关联文章，并沿用游标续载、搜索与来源筛选。专题筛选参与游标指纹，不能跨专题复用游标。待验证区域仅显示 pending 预测。

## 阅读路径与恢复

站内深入阅读携带受限的 `from` 返回路径；它只允许本应用的阅读页面，拒绝外部地址、API路径和异常长度。专题单篇与全部文章都携带同一 `topic`；监控文章按稳定信源编号 `sourceRef` 约束，返回后恢复信源、运行记录和标签。收藏文章使用 `saved=1`，通过只读POST传递当前浏览器的收藏ID集合（不放进地址栏）；选择集合参与游标指纹，不能混用旧游标。

政策详情优先返回实际来源（专题、收藏、信源或筛选后的政策列表），直接访问时回政策库。返回列表路径包含当前文件编号和筛选条件。文章概览/正文标签、预测筛选/搜索/展开记录、监控详情标签/信号筛选/运行记录同步到URL；正文、专题摘要与政策全文展开状态及滚动位置在当前标签页内保存。切换新专题或新的筛选结果时仍从开头阅读。明确的返回入口与全局导航分别承担“继续原任务”和“切换工作区”。

首页展示洞察生成时间及历史标识，最近文章入库时间不冒充最新洞察时间。政策详情与速览先呈现适用主体、要求性质和已提取日期；缺失值不补推断，有原文引句时可直接定位核对。专题政策检索词可选择，候选文件显示实际命中的关键词；两者仍不等于已确认的适用关系。
