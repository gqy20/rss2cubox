# 阅读工作台

前端沿用 Next.js App Router，采用已确认的 B 风格：象牙白、陶土色与橄榄色，宋体编辑标题、无衬线阅读列表。全站使用 `app/journal/Shell.tsx` 和 `app/styles/journal.css`。

## 页面

| 路径 | 内容 |
| --- | --- |
| `/` | 刊物式首页、跨来源重点文章、最新洞察、政策阅读入口 |
| `/briefing` | 完整趋势、弱信号与建议，以及最近30期历史简报 |
| `/signals` | 搜索、来源/日期/标签/重要性筛选、滚动续载和点击阅读 |
| `/policies` | 政策全文库，按地区、阶段、文件类型和分析状态筛选 |
| `/policies/[id]` | 关键条款、原文引句、适用主体、日期与已抓取全文 |
| `/topics?id=...` | 信号簇文章与关键词匹配的候选政策对读 |
| `/predictions?id=...` | 验证窗口、支持条件、反证条件和实际复盘 |
| `/monitor` | 入库趋势、分析覆盖、科技/政策信源最近一次采集 |
| `/saved` | 当前浏览器收藏，使用 localStorage，不跨设备同步 |

首页与政策、专题、预测、监控在服务端读取 `LOCAL_DB_URL`。`lib/journal-store.ts` 使用共享连接池、连接/语句超时及参数化查询，按模块降级显示不可用状态，不用示例数据补齐。技术信号继续支持 `API_SOURCE` 非 local 时的 IC 读取；政策与监控仍需要本地 PostgreSQL。

列表和详情通过 `/api/reader/[kind]`（signals / article / policies / policy）读取。列表每批30条，通过游标续载；全文只在详情中读取（搜索列表只返回命中片段）。搜索和筛选在数据库截取批次前执行。客户端取消过时请求，避免快速切换时错配文章与标题。旧 `/api/signals` 与 `/api/predictions` 接口保持兼容。

## 数据口径

- 文章总量是已收录总数，不是今日新增；重点文章是 `importance_score >= 4`。
- 文章已有分析：`hidden_signal`、`reason`、`actionable` 至少一个非空，不把 RSS 描述直接视为 AI 分析。
- 政策已分析：`enriched_at IS NOT NULL`。预筛会跳过低相关文件，因此未分析数量不是待处理任务数。
- 专题政策来自实体/关键词检索，明确标记为候选关联，不推断政策适用性。
- 监控图表按北京时间的首次入库日期统计。来源结果取最后一次采集记录，超过24小时显示无更新提示，不能据此断言在线状态。
- 预测没有复盘时不显示命中率。日期缺失时显示未明确；不生成虚构的征集截止提醒。
- 刷新只读取数据库，不调用模型或触发采集。

## 本地验证

```sh
cd web
npm run dev
npm run test:run
npm run build
```

主要组件为 `Reader`（技术/政策列表与阅读）、`Predictions`、`TrendChart`、`Shared` 和 `Actions`。`journal-utils.ts` 中的来源多样性、来源 URL 校验与洞察归一化有单元测试；查询测试覆盖筛选参数化、分页、日期与关键词转义。

## 搜索交互

顶部是唯一的文章/政策搜索入口，范围可显式切换。首页等非列表页面按 Enter 或箭头提交；列表页输入停顿350ms后自动提交，Enter立即提交，中文组词期间不搜索。清空关键词保留筛选，重置筛选保留关键词。关键词、筛选和手动选择的记录使用URL保存，支持刷新与浏览器返回。

查询仅匹配标题、来源、摘要、分析、标签/实体与正文；政策同时匹配机构、适用主体和关键条款。内部ID、链接和评分字段不参与文本匹配。标题命中优先，其余命中展示截取片段与字段名称，关键词用原生mark高亮。`%`与`_`按普通字符处理。客户端取消旧请求并验证查询归属，避免过时结果覆盖当前查询。

## 连续阅读面板

`/signals` 与 `/policies` 占据完整视口，顶部搜索、精简页面标题和筛选固定；桌面端列表与详情正文分别滚动，详情标题及操作保持可见。手机一次显示列表或正文，进入正文后收起页面标题和筛选，保留搜索与返回入口。首页和独立政策详情仍使用普通页面滚动。

列表接近底部时自动请求下一批，另保留可键盘操作的“继续加载”作为辅助入口。追加不改变选中文章，失败后保留已有数据并原位重试，到底时展示结束状态。客户端按ID去重，切换查询时取消旧请求。

游标包含查询指纹、首次加载时间、标题匹配优先级、微秒时间戳和ID。PostgreSQL查询使用键集边界，限定首次入库时间不晚于本次浏览快照，避免新增入库记录打乱续载；既有记录的编辑仍可能影响排序，客户端另行去重。旧page参数保留兼容，新界面不显示页码。IC模式按规范化后的时间与ID续载，其入库快照能力取决于上游数据。

同一标签页内缓存最近6个查询的已加载列表与滚动位置，切换详情或路由后返回时恢复。硬刷新会开始新的阅读会话。页面可见时每60秒检查新内容，只显示更新提示，不自动插入列表；用户点击提示或刷新按钮后才更新浏览快照。

验证覆盖游标精度与查询绑定、续载去重/互斥、失败重试、过时请求、缓存恢复及新内容提示；浏览器实测桌面独立滚动、自动续载、政策详情返回和移动端返回位置。
